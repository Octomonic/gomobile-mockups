מפרט השליחה — JSON

1 הבקשה

  • POST עם Content-Type: application/json
  • אימות בכותרת: Authorization: Bearer <token>
  • הגוף: מערך JSON של אובייקטים — רשומה לכל שורה. במכירות: שורה לכל פריט בקבלה, כולל קוד הסוכן.
  • שמות השדות — כמו שהם אצלך. את המיפוי אנחנו עושים אצלנו; כל שדה שתשלח נשמר.
🔑 הטוקן נשלח בהודעה נפרדת.

3 דוגמה (מכירות)

POST /api/bgate/sales-data/sales
Authorization: Bearer <token>
Content-Type: application/json

[
  { "sale_id": "98211", "receipt": "55123", "date": "2026-07-06 12:31:00",
    "store": "DIZ", "agent": "1044", "barcode": "8806095689012",
    "qty": 1, "total": 3899, "phone": "0521234567" },
  { "sale_id": "98212", "receipt": "55123", ... }
]

השמות בדוגמה להמחשה בלבד — שלח את השמות שלך. תשובה תקינה: {"ok":true,"received":2,"accepted":2,...}

4 כללים

  • עד 500 שורות ל‑POST · עד 4MB לבקשה
  • שליחה חוזרת בטוחה — כפילות מדולגת, תיקון (אותו מזהה, ערך שונה) מעדכן. אפשר לשלוח פעמיים בלי נזק.
  • סדר גמיש — מכירה שהגיעה לפני החנות/הסוכן שלה ממתינה ונקלטת לבד כשהם מגיעים.
  • שגיאות: 401 טוקן שגוי · 413 גדול מדי · 415 לא JSON

5 איך מתקדמים

  • דוגמה קטנה מכל סוג — נמפה את השדות אצלנו ונאשר.
  • אחרי האישור — היסטוריה 3 שנים ומשם דחיפה שוטפת.
  • חנויות: קוד + שם מספיקים — את שאר הפרטים אנחנו משלימים מהאתר.
  • מלאי — בשלב אחרון, כמו שסיכמנו.
